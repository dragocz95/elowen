# Usage & Costs

Elowen reports token usage, cache usage, provider-reported cost, and generation speed for your brain sessions. The CLI overlay and web views are related, but they do not all use the same scope or calculation:

- **Conversation** is the live session you are viewing.
- **Models** summarizes persisted brain-session usage for your account. The web view can filter it by date.
- **Context** explains what currently fills the active conversation's context window.
- **Origin** accounting is a separate administrator-only rollup and is not an exact checksum of the other views.

## Open the usage views

### CLI and web chat

In a CLI chat, enter **`/stats`**. Use **←** and **→** to switch between **Conversation**, **Models**, and **Context**. Enter **`/context`** in the CLI to open the Context section directly.

In web chat, use the **Stats** command or the Stats control in the chat UI to open the same three-section modal. The chat-platform adapters return the session information as a message rather than drawing the modal.

### Web Stats page

For a longer-term view, open **Stats** in the web UI. It provides model usage over a selectable date range, including:

- total tokens,
- cache volume,
- total provider-reported cost,
- models used, and
- average generation speed.

The daily trend supports at most **90 days**. These views do not provide a project selector.

The Stats page is a browser view over Elowen's core usage routes; it is not a separate accounting system.

## Conversation

The Conversation section describes the active session:

| Value | Meaning |
| --- | --- |
| **Model** | The provider and model answering this conversation. |
| **Context** | Tokens currently occupying the context window, the configured window size, and the percentage used. |
| **Session tokens** | Total tokens reported for the session. |
| **Input tokens** | Input tokens sent to the provider. |
| **Output tokens** | Output tokens generated by the provider. |
| **Cache hit rate** | The share of input served from the provider's prompt cache. |
| **Cost** | Provider-reported cost when available. Missing cost is shown as unavailable, not as `$0`. |
| **Generation speed** | Measured output tokens per second. Untimed history and aborted generations are excluded. |

A live session may have no usage data yet. In that case the relevant fields show `—` until a request has been measured.

## Models

Models shows one row per model and runtime, with tokens, cache volume, measured speed, and cost. Rows are ordered by token usage and include totals.

The data comes from persisted brain-session records for the authenticated account. It is **not** a universal ledger of every executor or every activity performed by the daemon. A model total also does not identify a person from an IP address or prove which project caused the usage.

Cost is included only when the provider reports it. Elowen does not calculate a replacement price from a local price list for this view. A provider without a reported cost appears as unavailable.

Speed is a duration-weighted average over measured output, not an arithmetic average of model rates. If no generation has both measured duration and output tokens, speed is shown as `—`.

## Context

Context shows what fills the active conversation's window:

- the configured **context window**;
- the provider's **reported token count** for the last request, when available;
- an estimated breakdown of **System prompt**, **Tool schemas**, **Your messages**, **Replies**, **Tool output**, and **Other**;
- remaining **Free space**;
- the token level at which Elowen compacts the conversation, when available; and
- the heaviest tools, split into schema, call, and result tokens.

The category figures are estimates made by Elowen. Providers use their own tokenizers, so the estimated breakdown may not equal the provider's reported count. The Context section describes a live session; with no active prompt it shows that there is nothing to measure.

For more about compaction, see [Brain & Chat](brain-chat).

## Cache hit rate and cache volume

Cache accounting differs slightly by surface:

- In the **web** usage bars, cache hit percentage is `cacheRead / (cacheRead + input)`.
- In the **CLI Conversation** view, it is `cacheRead / (cacheRead + cacheWrite + input)`.
- The web **cache volume** total is `cacheRead + cacheWrite`.

Consequently, the CLI and web percentages can differ even when they cover the same activity. Cache figures describe provider accounting; they are not a promise that a request was free.

## OAuth subscription windows

OAuth-backed providers can expose subscription or rate-limit windows instead of per-token API billing. Current OAuth provider types include Anthropic, GitHub Copilot, OpenAI Codex, and Kimi; the exact windows depend on what the provider returns.

Elowen displays those windows in two places:

- the CLI telemetry rail for the active provider; and
- **Settings → Elowen AI**, on the connected OAuth account row.

A provider may report a five-hour window, weekly windows, or another shape. Elowen does not raise or reset these limits. Window meters become warning-colored at **70%** and danger-colored at **90%**; hovering the meter shows the provider's reset time.

Readings are cached for about one minute. If polling fails, Elowen keeps the last successful result and marks it as a **cached reading** until the next successful refresh.

## Statusline and telemetry

The CLI telemetry rail shows live session information while you work. To configure the shared statusline, use **`/statusline`**.

The statusline configuration supports these toggles:

- `showModel`
- `showContext`
- `showTokens`
- `showSpeed`
- `showCost`

All are disabled by default. The CLI editor exposes context, tokens, speed, and cost; the model name is already displayed elsewhere in the CLI. The shared configuration also applies to the web chat dock. Changing it requires administrator access.

## Origin accounting and retention

Origin accounting is available only to administrators because it can contain client IP addresses and spans accounts on the instance. It is a separate write-time rollup, with values such as:

- `ip` — an address obtained from proxy headers;
- `local` — no forwarding header, typically a local or loopback request;
- `internal` — cron, boot recovery, or sub-agent work without an HTTP request;
- `platform:<name>` — Discord, Telegram, Teams, WhatsApp, or another chat platform; and
- `redacted` — an address whose privacy-retention period has elapsed.

An IP identifies a connection, not a person. Usage history from before origin tracking began has no origin attribution and cannot be reconstructed. Origin totals are intentionally not expected to match the model or day totals exactly.

Runtime retention settings are under **Settings → Elowen AI → Runtime**:

- `runtime.limits.originIpRetentionDays` — how long an origin IP remains readable; default **30 days**, range **1–365**;
- `runtime.limits.eventRetentionDays` — how long origin rows are retained; default **30 days**, range **1–365**.

The hourly cleanup replaces expired IP addresses with `redacted` while preserving their token and cost totals. It later removes the complete origin rows when the event-retention period expires. The proxy-trust setting is `security.trustProxy`, whose default is `true`.

## Reset usage

If you are an administrator and use the usage reset control, Elowen clears your own message-derived usage and origin rows. It does **not** delete conversations, transcripts, or messages. Resetting also cannot restore token or cost fields that have already been removed from stored messages.

## Reduce usage

- Use **`/model`** to switch routine work to a less expensive model when appropriate.
- Use **`/compact`** during long conversations to replace older history with a summary and free context space. See [Brain & Chat](brain-chat).
- Check **Models** after introducing automation. Remember that this view covers persisted brain-session usage, not every type of daemon work.
- Treat unavailable cost as unknown. It is not evidence of zero cost; the provider's invoice is authoritative.
