# Channels

Channels let people use the same Elowen instance from Discord, Telegram, Microsoft Teams, or WhatsApp. Each channel is a plugin that turns platform messages into Elowen turns and sends the response back through that platform.

## Choose a channel

- **[Discord](channels-discord)** — a bot connected to a Discord server.
- **[Telegram](channels-telegram)** — a long-polling bot for direct chats and groups.
- **[Microsoft Teams](channels-teams)** — an Azure Bot webhook for personal chats, group chats, and team channels.
- **[WhatsApp](channels-whatsapp)** — a paired WhatsApp account for direct chats and groups.

Enable and configure channel plugins in **Settings → Plugins**. Each plugin page below describes its connection settings and platform-specific controls.

## Access and identity

A channel policy decides whether a platform sender is admitted and whether they are an operator for shared-channel controls. Policies use the identity format native to each platform, and the first matching policy wins. An unmapped sender is ignored.

A human sender must also be linked to an Elowen account before a brain turn can run. The linked account supplies that person's project access, tool permissions, and—when enabled—personal memory. A channel role or sender policy is not an account and does not grant project or tool permissions by itself.

The `admin` flag on a channel policy is for operator controls in that shared channel, such as model and reasoning pickers, context binding, and platform administration features where supported. It does not turn a shared channel into the instance owner's private chat.

## Commands shared by channels

The exact menu is generated by the running daemon, so unavailable commands are not shown. These commands are common on the supported chat surfaces:

| Command | Purpose |
|---------|---------|
| `/new` | Start a fresh channel conversation. |
| `/stop` | Stop the running turn. |
| `/stats` | Show the current model, context usage, and usage. |
| `/compact` | Summarize the conversation to free context. |
| `/fast` | Toggle OpenAI OAuth priority processing; use `on` or `off` when the surface accepts an argument. |
| `/model` | Open the platform's model picker. |
| `/reasoning` | Open the reasoning-effort picker. |
| `/context` | Open a picker of the invoking sender's own conversations. |
| `/help` | Show commands available on that surface. |

`/display` is available on Discord, Telegram, and Microsoft Teams. `/voice` is available on Discord and Telegram only. WhatsApp has neither command.

Most channel pickers and questions are operator-gated because their settings affect everyone in a shared chat. Discord uses native select menus and buttons, Telegram uses inline keyboards, Teams uses Adaptive Cards, and WhatsApp uses numbered text replies.

## Conversation behavior

- `/context` **moves** one of the invoking sender's own conversations into the channel; it does not copy the history. The server checks ownership again when binding.
- A channel session is separate from the user's normal Web UI or CLI conversation until `/context` binds one into the channel.
- Direct 1:1 chats are treated as personal only when the platform identity is verified and linked to the sender's Elowen account. Groups and channels are shared conversations.
- Replies and quoted messages include the referenced message as context where the platform supplies it.
- Long responses are split according to the platform's message limit. Generated images and supported files are sent as platform attachments.
- Each platform has its own media limits and history behavior. Do not assume that a setting from one channel applies to another.

## Common presentation settings

Discord, Telegram, and Teams expose these global plugin settings, with per-channel or per-chat overrides through `/display`:

- `toolActivity` — `off`, `status`, or `live`.
- `answerMode` — `final` or `live`.
- `toolOutput` — `hidden`, `summary`, or `tail`.
- `toolMessageMode` — `single` or `per_tool`.

All four platforms can show processing reactions, a runtime footer, and optional model reasoning. Their defaults and supported controls are documented on each platform page.
