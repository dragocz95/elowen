# Scope

Audited the registry Discord plugin at `/var/www/elowen-plugins/plugins/discord` together with the host web/core surfaces that render and persist registry-plugin configuration. The audit covers the generated Settings → Plugins → Discord workspace, all declared config fields, modal/drawer-backed editors, the Discord destination catalog API, and Discord-owned per-channel state mutations. The plugin has no `web` manifest block or custom browser bundle; it uses the host schema-driven editor (`elowen-plugin.json:49-319`, `index.mjs:31-58`). It also has no `userConfigSchema`, so there is no per-account Discord settings form (`src/api/routes/plugins/index.ts:365-415` only applies to manifests that declare one).

# Missing or inconsistent auto-save

- **Modal feedback is not colocated with the edit.** The shared draft has saving/saved/error+retry states, but `PluginDetail` renders `AutoSaveStatus` only in the workspace toolbar (`PluginDetail.tsx:102-111`). Modal-backed editors expose only a `Done` button (`PluginConfigEditor.tsx:620-625`), so while Role policies, destination selection, and document-shaped fields are open, the user can be looking at an obscured status or miss an error/retry affordance entirely. Persistence still happens, but the drawer experience is only partially compliant with the required visible feedback contract.
- **Channel-state persistence has no user-facing failure path.** `StateStore.patch` correctly writes atomically and rethrows failures (`stateStore.mjs:7-11,21-31`), but `onFrame` catches interaction failures only to log them (`adapter.mjs:343-373`). A failed `/voice`, `/display`, `/model`, `/reasoning`, or `/new` write can therefore leave the Discord interaction without a clear retry instruction.
- **Runtime validation is incomplete for autosaved config.** `applyConfigPatch` validates only numbers, timezones, and token lists (`src/api/routes/plugins/index.ts:73-84`); it does not validate enum membership, booleans, strings, model/provider/destination shape, or `rolePolicies`. The Role policies editor can autosave a newly added blank row (`PluginConfigEditor.tsx:352-354`), and the API accepts malformed role-policy objects. The form is trusted as the main validator even though the write endpoint is the trust boundary.
- **The model component submit is not fully catalog-validated.** The picker rechecks admin status but persists any non-empty `provider::model` payload (`adapter.mjs:797-802`), rather than confirming that the pair exists in the current model catalog. This is an adjacent persistence-integrity gap for channel state.
- **Required-field enforcement is UI-only.** The setup checklist computes missing required fields (`PluginDetail.tsx:59-64`), but the config write route does not reject an unset required value; it only applies the patch (`src/api/routes/plugins/index.ts:502-517`). This is acceptable for staged setup but should be explicit because an enabled Discord plugin can remain persisted without a usable bot token.
- **Secret handling is intentionally different from normal autosave.** The generic draft sends a replacement token after the debounce, while secrets are write-only and cannot be cleared with an empty value (`src/api/routes/plugins/index.ts:62-85`). This is safe against read-back leakage, but credential rotation is a reasonable explicit-commit exception because partial typing can trigger repeated reload/connect attempts.

# Legitimate exceptions

- `botToken` is a credential and may reasonably require an explicit replacement/commit action. It must remain write-only; the current masked representation and server-side “empty means keep” rule are correct.
- Role-policy removal is destructive to admission and administrative access, so the confirmation dialog is justified. Immediate commit after confirmation avoids resurrecting a deleted row from an older debounced snapshot (`usePluginConfigDraft.ts:83-101`).
- `/new` is an explicit destructive command and should remain immediate rather than debounced.
- `/model`, `/reasoning`, `/voice`, and `/display` are explicit shared-channel commands. Immediate durable writes are appropriate; they need reliable acknowledgement/error handling rather than a web-style debounce.
- `ManageSelectionModal` and the Role policies modal may retain “Save changes”/“Done” as UI staging or navigation controls. They should not become a second persistence mechanism: the canonical write remains the shared config draft.

# Reusable existing pattern

- `usePluginConfigDraft` is the correct shared pattern: server-seeded state, 900 ms bounded debounce, serialized full snapshots, flush on unmount, JSON validation, and immediate `commitValue` for confirmed destructive changes (`web/lib/usePluginConfigDraft.ts:37-112`).
- `useAutoSaveStatus` provides the required state machine and retry behavior, including queued follow-up writes that prevent stale responses from rolling the server back (`web/lib/useAutoSaveStatus.ts:7-17,45-67,85-105`).
- The host uses one server-side `applyConfigPatch` helper for instance and per-account semantics, preserving omitted fields and write-only secrets (`src/api/routes/plugins/index.ts:62-105,392-415`).
- `StateStore` is a sound immediate-persistence primitive for channel commands: temp-file/atomic-rename writes, cache update only after success, and rethrow on failure (`packages/plugin-shared/stateStore.mjs:3-31`).

# Tests and gaps

Existing evidence:

- Generic plugin-editor tests prove direct controls autosave (`web/tests/modules/settings/PluginDetail.test.tsx:199-245`), modal text fields autosave (`:383-394`), token-list edits preserve/normalize values (`:328-369`), and model/provider/destination pickers use shared controls (`:95-106,372-380,487-505`).
- Role-policy tests prove deletion is not mutated before confirmation, preserves the draft on save failure, and reports delayed activation (`web/tests/modules/settings/PluginConfigEditor.test.tsx:94-122`).
- Draft tests cover invalid JSON, secret omission, immediate commit failure/success, delayed activation, and serialized full-snapshot race protection (`web/tests/modules/settings/usePluginConfigDraft.test.tsx:31-105`).
- Shared state tests cover atomic persistence, corruption logging, write failure propagation, and recovery on a later write (`tests/plugins/sharedStateStore.test.ts:13-69`). Shared display tests cover default resolution and cleanup semantics (`tests/plugins/sharedDisplay.test.ts:25-35`).
- Discord tests cover registration without a token, destination listing, opaque destination compatibility, and legacy token-list compatibility (`/var/www/elowen-plugins/tests/discord.test.ts:14-89`). The Discord E2E exercises `/new` and other slash-command routing (`/var/www/elowen-plugins/tests/e2e/discord/run.mjs:194-200`).

Gaps:

- No Discord-specific test exercises `PATCH /plugins/discord/config` with every declared field, malformed role policies, invalid enum/boolean/model values, required-field behavior, or secret rotation semantics.
- No adapter test simulates a failed `StateStore.patch` during each state command and verifies a visible Discord error/retry response.
- No UI test proves saving/saved/error+retry remains visible and operable while the Role policies or destination modal is open.
- No test proves `/model` rejects a forged or stale provider/model pair at component submit.

# Recommended migration notes

- Keep the shared 900 ms autosave for non-secret Discord config and do not introduce a Discord-specific web bundle.
- Move `AutoSaveStatus` (or a compact equivalent) into the modal/drawer chrome for modal-backed fields, while retaining the workspace toolbar indicator for direct fields.
- Treat `botToken` as an explicit-save-justified credential field, or introduce a credential-aware commit path that never persists partial replacements; preserve the current write-only and “empty keeps existing” semantics.
- Add runtime validators at the plugin-config write boundary for Discord enums, booleans, provider/model/destination values, and the `rolePolicies` structure; separately enforce or clearly document required bot-token setup state.
- Wrap Discord channel-state writes so a failed atomic patch produces an acknowledged, user-visible error with a retry instruction, and validate `/model` selections against the current catalog before persisting.
- Add focused regression coverage for modal feedback, state-write failures, forged model selections, and malformed config payloads before changing the shared host behavior.
