# Host auto-save primitives audit

## Scope

Audited the shared auto-save implementation in `/var/www/elowen/web`, the host runtime exposure used by registry bundles, and the installed registry UI-kit contract (`elowen-plugin-ui-kit` 0.6.0 under `/var/www/elowen-plugins/node_modules`). The audit covers the debounce/controller hook, status indicator, status aggregation helper, the shared plugin-config draft, supporting spinner/layout adapters, and registry-side structural mirrors and test-runtime copies.

Individual settings/account forms were sampled where they establish adoption, validation, lifecycle, or status-aggregation behavior. The registry's cronjob and Microsoft Teams panels were included as the direct external consumers of the runtime contract.

## Missing or inconsistent auto-save

- **The host hook is the canonical behavior.** `useAutoSaveStatus` deliberately separates seed readiness from validity (`:19-24`), suppresses the seed run (`:70-83`), serializes changes that arrive during an in-flight save (`:45-67`), flushes on teardown (`:90-105`), and exposes Retry/Flush (`:26-30, :85-105`). This is the behavior registry panels should consume, not reproduce.
- **Retry bypasses the current validity gate.** `retry` calls `run()` directly (`/var/www/elowen/web/lib/useAutoSaveStatus.ts:104`), while `savable` is enforced only inside the dependency effect (`:70-80`). A failed valid edit followed by an invalid edit can leave the error Retry button active; Retry can then invoke a callback despite `savable: false`. `ContextWindowModal` has a callback that becomes a no-op when invalid (`/var/www/elowen/web/modules/settings/ContextWindowModal.tsx:28-31`), so this path can report `saved` without persisting the invalid value. There is no regression test for retry-after-invalid-edit.
- **Composite Retry behavior is inconsistent.** `combineSaveFeedback` returns the first error item (`/var/www/elowen/web/lib/saveFeedback.ts:8-10`), so a shared indicator offers only that error's retry when multiple child saves fail. The three manual folds retry every failed child (`BrainRuntimeSection.tsx:149-154`, `MemorySection.tsx:98-101`, `CliSection.tsx:148-154`). Status precedence is duplicated and the user-visible retry result depends on which aggregation path owns the surface.
- **The registry UI-kit does not type the auto-save ABI.** The published contract types only define the page callback's status union (`index.d.ts:94-100`). Runtime `components` and `hooks` are generic records (`:160-164`), so `AutoSaveStatus` props, `useAutoSaveStatus` options/result, and `usePluginConfigDraft` are absent from the package-level contract. Plugin-local `runtime.ts` files consequently repeat literal unions and hook/component shapes.
- **The registry fixture is a second implementation.** `tests/ui/useAutoSaveStatus.ts` explicitly copies the host hook (`:1-4`) and `hostComponents.tsx` explicitly ports the indicator (`:772-786`). The copy is valuable for behavior tests without a host checkout, but the parity guard checks runtime names only and explicitly does not check props (`/var/www/elowen-plugins/tests/hostRuntimeParity.test.ts:14-18, :31-33, :194-205`). No guard compares the copied hook or status behavior with the host source.
- **Status-component tests are thin.** The route integration test proves a reported page failure renders an alert and Retry (`/var/www/elowen/web/tests/app/pluginHostPage.test.tsx:141-160`), and `SpatialControlDeck` proves the retry reaches its callback, but there is no focused host `AutoSaveStatus` test for all four states, stable idle live-region behavior, or translated accessibility output.

## Legitimate exceptions

- **Immediate action writes:** model selection and retention preset changes are explicit single actions and may use immediate mutation (`/var/www/elowen/web/modules/account/AccountView.tsx:217-230`; `/var/www/elowen/web/app/settings/page.tsx:250-269`). They are not ordinary text/form drafts and should not be forced through a debounce merely for consistency.
- **Atomic or destructive config operations:** `usePluginConfigDraft.commitValue` flushes older pending state, writes one replacement immediately, and updates the draft only after acceptance (`/var/www/elowen/web/lib/usePluginConfigDraft.ts:83-101`). This is appropriate for ordered authorization/policy-style edits; ordinary fields remain debounced auto-save.
- **Delete/run/upload/password/consent interactions:** these are commands or externally verified credentials, not ordinary settings edits. Cron deletion explicitly waits for an in-flight save and disables the unmount flush from resurrecting the row (`/var/www/elowen-plugins/plugins/cronjob/web-src/JobsSettings.tsx:288-321, :354-363`).
- **Registry test copies:** the registry cannot import host source in its test environment, so the fixture copies are an understandable test seam. They are still maintenance duplicates and should remain clearly subordinate to the host implementation.

## Reusable existing pattern

- Use `/var/www/elowen/web/lib/useAutoSaveStatus.ts:7-24, :45-105` for every validated draft: seed from server, pass `ready`, pass `savable` when invalid input must be held, keep the save callback in a ref, and expose the returned status/retry/flush through the nearest shared surface.
- Use `/var/www/elowen/web/components/ui/AutoSaveStatus.tsx:10-27` for the visible state. It already provides the canonical translated copy, polite `Saving…`/`Saved` announcements, alert semantics, and Retry affordance.
- Use the host runtime rather than importing a second React/query context: `/var/www/elowen/web/lib/pluginUi.tsx:338-347` exposes the hook and draft, while `:294-305` exposes the indicator and spinner.
- For full-snapshot plugin config, reuse `/var/www/elowen/web/lib/usePluginConfigDraft.ts:37-80`: it combines JSON validation, serialized writes, and refetch-safe draft ownership in one place. The registry Teams panel demonstrates the intended shape through its local structural contract (`/var/www/elowen-plugins/plugins/msteams/web-src/runtime.ts:81-95`).
- For a shared header/deck, report the child state upward and render one indicator at the host-owned boundary (`/var/www/elowen/web/app/settings/page.tsx:139-145, :369-373, :479`; `/var/www/elowen/web/app/p/[plugin]/[[...rest]]/page.tsx:40-44, :121-143`).

## Tests and gaps

- `web/tests/lib/useAutoSaveStatus.test.tsx:7-14` covers seed suppression and debounce; `:16-29` covers saved/error/retry; `:32-57` covers unmount flush and in-flight completion; `:59-82` covers React `<Activity>` hide/show; `:84-102` covers latest-generation terminal status.
- `web/tests/modules/settings/usePluginConfigDraft.test.tsx:31-105` covers invalid JSON, secret omission, confirmed immediate commit, pending activation, and serialized full-snapshot saves.
- `web/tests/app/pluginHostPage.test.tsx:141-160` covers host page rendering of a plugin-reported failure and Retry; `web/tests/components/ui/SpatialControlDeck.test.tsx:108-112` covers the deck Retry callback.
- Registry surface parity is guarded by `/var/www/elowen-plugins/tests/hostRuntimeParity.test.ts:161-214`, but that guard compares runtime names and API version, not prop shapes or behavioral equivalence. The file itself documents this residual gap at `:31-33`.
- There is no focused test for `combineSaveFeedback`, including the multiple-error retry case. There are no focused tests for host `AutoSaveStatus` rendering, and no test for `retry()` while `savable` is false.
- There is no package-level type test for `AutoSaveStatus`, `useAutoSaveStatus`, `usePluginConfigDraft`, or `SaveStatus`; the UI-kit's generic records allow plugin-local contracts to drift while still typechecking.

## Recommended migration notes

- Keep `/var/www/elowen/web/lib/useAutoSaveStatus.ts` and `/var/www/elowen/web/components/ui/AutoSaveStatus.tsx` as the sole production sources of controller and indicator behavior. Do not add a second production hook or status component to the UI-kit package.
- Fix or explicitly guard Retry against `ready`/`savable` before treating the hook as the complete validation contract; add a regression test for a failed save followed by an invalid edit.
- Decide one composite-retry contract. The safest shared behavior is to preserve the manual folds' “retry every failed child” semantics, then extend `combineSaveFeedback` (or add a dedicated composite helper) rather than silently changing those sections to first-error-only retry.
- Publish structural UI-kit types for the shared auto-save ABI: a `SaveStatus` alias, status component props, hook options/result, and plugin-config draft shape. Keep runtime maps dynamic if desired, but let plugin-local runtime modules import the shared contracts instead of repeating literal unions.
- Treat the registry hook/status copies as test fixtures only. Add a focused fixture contract test or a generated/synchronized check so debounce, retry, teardown flush, invalid gating, and accessibility semantics cannot drift from the host.
- Add a focused host status-component test covering idle/saving/saved/error, Retry, live-region roles, and the translated labels; keep existing route/deck integration tests for ownership and placement.
