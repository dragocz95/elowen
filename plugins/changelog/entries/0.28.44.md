Managed Projects and persistent Sites now use one completed systemd-nspawn runtime. Their files, installed
packages and configuration live on durable disks, host preparation is visible in Sandbox, and deletion waits
until every privileged resource is really gone.

### Managed environments

- New environments are created from verified published root filesystems and run as systemd-nspawn machines.
  The removed Podman runtime is no longer offered. An older environment that still belongs to it must be deleted
  and recreated.
- The root filesystem survives stop, start, envelope recreation and resource changes. Snapshots and restores
  preserve the environment data and verify it before the restored machine starts.
- **Settings → Plugins → Sandbox → Host runtime** shows whether the host and required root filesystems are ready.
  An administrator can provision the fixed runtime from that page through one bounded action.

### Networking

- A Project environment can use shared networking or fully isolated networking. Isolated environments have no
  outbound access and accept no inbound port mapping.
- Administrators can add explicit TCP or UDP inbound mappings to a shared environment. The host denies other
  inbound traffic and applies the declared mappings through native machine settings.
- DNS uses the host uplink resolver through a read-only binding. Readiness reports DNS, firewall and machine
  prerequisites separately, so a failed start names the missing host capability.

### Reliability and cleanup

- Environment deletion keeps its durable checkpoint until storage, machine settings and runtime artifacts are
  absent. Only then is its uid range released for later reuse.
- Site deletion remains retryable until the publication socket, gateway record, nginx configuration and
  certificate are removed. A temporarily unavailable Sandbox or gateway control is reported as a cleanup error.
- Publication creation, recovery and release are serialized, preventing a recovered forwarder from returning
  after its publication was deleted.

### Compatibility

- The Sites plugin requires core **0.28.44**. Host readiness and provisioning now live in Sandbox, so the Sites
  setup page links there instead of exposing a second setup API.
- Plugin UI API remains **16**, shared-helper API remains **4**, and the minimum Node.js version remains
  **22.12.0**.

### Registry plugin releases in the same period

- **sites 0.11.3-chetty.1** uses the completed Sandbox runtime contract and keeps destructive cleanup durable.
