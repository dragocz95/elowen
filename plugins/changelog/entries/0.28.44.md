This release completes the machine runtime for managed Projects and persistent Sites, makes administrator
account switching safer, and lets you continue your own nested sub-agents directly from their transcript.
Usage speed and background process cleanup now report only what Elowen has actually verified.

### Managed environments

- New environments are created from verified published root filesystems and run as systemd-nspawn machines.
  The removed Podman runtime is no longer offered. An older environment that still belongs to it must be deleted
  and recreated.
- The root filesystem survives stop, start, envelope recreation and resource changes. Snapshots and restores
  preserve the environment data and verify it before the restored machine starts.
- **Settings → Plugins → Sandbox → Host runtime** shows whether the host and required root filesystems are ready.
  An administrator can provision the fixed runtime from that page through one bounded action.

### Networking

- A Project environment can use shared networking or fully isolated networking. Isolated environments have no
  outbound access and accept no inbound port mapping.
- Administrators can add explicit TCP or UDP inbound mappings to a shared environment. The host denies other
  inbound traffic and applies the declared mappings through native machine settings.
- DNS uses the host uplink resolver through a read-only binding. Readiness reports DNS, firewall and machine
  prerequisites separately, so a failed start names the missing host capability.

### Sub-agents and workflows

- In the web app and CLI, you can open your own delegated child at any nesting depth and continue or steer it
  from the transcript on screen. Stop, model selection and skill turns target the viewed child; actions that
  belong to the parent conversation are refused with an explanation.
- Write controls appear only after Elowen verifies the full owner ancestry and the access you hold now. A child
  opened from another account or a read-only session stays read-only, and revoked Project access cannot be
  reused through an older delegation.
- `Delegate`, `DelegateContinue` and `WorkflowStart` now run in the background by default when Elowen can deliver
  the result in a later turn. Set `background: false` to wait for the result inline. A surface without later
  delivery stays in the foreground so the result is not lost.
- Background commands started by a sub-agent now update the owner process view immediately. Conversation
  deletion waits for confirmed cleanup across the whole delegated tree, and a crashed runner leaves containment
  information that Elowen uses to stop surviving processes.

### Account and plugin administration

- **Sign in as** and **Return to administrator** now switch identity inside the app without a page reload. Open
  tabs clear account-scoped streams and cached data as the transition starts, then load the new identity or
  return to the previous one if the request fails.
- The impersonated session carries only an opaque, one-time return proof, never a reusable administrator
  credential. Returning revokes the impersonated session and creates a fresh administrator session; the same
  proof can repeat only the already completed exchange during a short lost-response retry window.
- Elowen refuses to disable or remove the last provider of a control while another enabled plugin depends on
  it, and names the plugin that must be disabled first.
- The plugin Data panel stops large recursive measurements at a bound and labels totals that are partial or
  include unreadable entries instead of failing or showing an empty result.

### Usage speed

- Effective tokens per second measures the complete logical model request from initiation to its terminal
  response. Provider queueing, response-header wait, prompt processing, automatic retries and backoff are
  included; tool execution between model calls is excluded.
- Only successful measured requests contribute. Failed or aborted retry prefixes, older compacted samples and
  legacy post-header rates stay unknown and appear as unavailable instead of changing the effective average.

### Reliability and cleanup

- Environment deletion keeps its durable checkpoint until storage, machine settings and runtime artifacts are
  absent. Only then is its uid range released for later reuse.
- Site deletion remains retryable until the publication socket, gateway record, nginx configuration and
  certificate are removed. A temporarily unavailable Sandbox or gateway control is reported as a cleanup error.
- Publication creation, recovery and release are serialized, preventing a recovered forwarder from returning
  after its publication was deleted.
- Root filesystem artifacts are rehashed before privileged extraction. Site data import and export bind to
  verified filesystem objects, reject unsafe or oversized archives, require imports to target a stopped
  environment and replace the data tree atomically.

### Compatibility

- The Sites plugin requires core **0.28.44**. Host readiness and provisioning now live in Sandbox, so the Sites
  setup page links there instead of exposing a second setup API.
- Plugin UI API remains **16**, shared-helper API remains **4**, and the minimum Node.js version remains
  **22.12.0**.

### Registry plugin releases in the same period

- **sites 0.11.3-chetty.1** uses the completed Sandbox machine runtime contract and keeps destructive cleanup
  durable.
- **editor 0.4.3** adds separate Project and System roots for managed projects, loads folders on demand and
  reports directory failures instead of presenting an empty tree.
