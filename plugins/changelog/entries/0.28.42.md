This release rebuilds the ground a managed Project and a published Site stand on: environments are now real
systemd machines with a disk of their own, which you can snapshot and restore. Alongside that, delegated work
runs in the background by default, you can see how fast a model actually answers, and publishing a site no
longer claims an address works before its certificate exists.

### Environments are machines now

A managed Project and a published Site each run in a persistent environment. Until now that was always a
rootless container; from this release a new environment is a **systemd-nspawn machine** with a persistent disk
of its own. The Project's environment panel names which one an environment uses, as a badge reading **Machine**
or **Container**.

You do not choose. The runtime is decided once, the first time an environment is built, and every environment
created from now on is a machine. **Environments you already have keep running exactly as they are**, under
the old runtime, until an administrator deliberately migrates them — and a migration moves the environment
over the same disk without copying your data.

### Snapshots you can actually restore

A persistent disk can be snapshotted from the project's row menu in the register, with **Create snapshot**,
and a complete snapshot can be restored in the Project's environment panel with **Restore snapshot**. Each
part of the disk is copied with its own fingerprint, there is a
free-space check before the copy starts, and a restore verifies every fingerprint against the snapshot and
refuses rather than leaving you with a half-restored disk. Execution is paused while a snapshot is taken, so
what you get is the disk as it stood at that moment.

### Delegated work happens in the background

When Elowen hands a task to a sub-agent, that call no longer blocks the conversation. It starts the sub-agent,
carries on, and the result is delivered into the conversation when the sub-agent finishes — so a long piece of
research no longer stalls everything behind it. The same is true of continuing an existing sub-agent and of
starting a workflow. Work that genuinely cannot continue without the answer still waits.

There is also a new built-in **review** role. Ask Elowen to have a change reviewed and it can run an
adversarial reviewer over the diff, which reads the tests and the surrounding code, runs the checks itself, and
comes back with findings labelled by severity and a verdict.

### How fast the model really answered

The speed figure in the statusline and in the stats view is now an **effective** rate: the provider's own
output tokens divided by the entire wait for that answer, including the time before the first token arrives
and any retry the provider needed. The time Elowen spends running tools between model calls is left out, so
the number tells you about the model rather than about the work around it. The stats view in the CLI adds a
**first content** row — how long you waited before anything started streaming at all.

Because the rate covers the whole wait, it reads lower than the old figure did. The old one started counting
only after the provider's headers came back, which quietly hid the slowest part.

### Sites tell you the truth about HTTPS

Publishing a site and getting its certificate are two separate things, and Elowen used to announce the address
as soon as the site was published. Now it checks: it opens a real TLS connection to the gateway under the
site's own hostname and looks at the certificate actually served. You get one of three answers — **ready**,
**pending** or **error** — and the address is presented as usable HTTPS only when it is ready. A site you
publish right now will read as pending for a short while, which is the honest answer.

Deleting a site now also cleans up after it: the address stops working, the site's entry in the web server is
retired and its certificate is deleted, along with every release. **The source folder in your Project is left
untouched.** While the cleanup runs the site is out of reach rather than half-present, and a deletion asked for
in a context that cannot do the privileged part is finished by Elowen itself instead of being silently
dropped.

One fix worth naming on its own: Elowen can now tell you a site's real address no matter which of its own
processes answers you. Before, a task running in a sub-agent could not look the address up and refused to
publish or reported the hostname as unavailable, while the very same site worked fine.

### Smaller things you may notice

- **Release notes now track who has read them.** An administrator sees, beside each release, how many people
  have read it and who, and can mark a release unread for everyone. That also marks every later release as
  new again, badge included.
- **A new conversation asks which project it belongs to**, and the answer sticks to the conversation. A
  scheduled job runs in the project it was filed against.
- **The Project register took over the environment lifecycle.** Starting, stopping and the rest happen on the
  project's own row instead of inside a drawer, and a long operation shows the steps it is really taking.
- **Background shell commands no longer get lost.** A command started inside a sub-agent is now visible to
  Elowen itself, so it can be listed, read and stopped from the process view instead of running on
  unattended. You still only ever see your own processes.
- **Usage attribution is fairer.** A sub-agent's turns are billed to whoever asked for the work, not to
  Elowen's internal activity, and the dashboard bucket for work with no request behind it is now plainly
  labelled **Internal**.
- **Prices and reasoning levels resolve correctly** for Together and Fireworks models, for Gemini 3
  generations above 3.5, and for the DeepSeek models addressed by their native names. No new model appeared —
  these were rows Elowen was failing to find.
- Direct links to a project open properly, the People tab says when a directory is still loading or failed
  instead of looking empty, and an environment operation finishes even if you closed its progress window.

### For administrators

A new environment needs the machine runtime present on the host: a privileged helper, the machine unit
template and a permission rule, all installed and provisioned by `elowen install` and `elowen update`. On a
host that does not carry it, creating an environment is **refused with the missing piece named**, rather than
quietly falling back to the old runtime — so run the update before you expect to create one. The old runtime
is still needed as the image store.

Machine environments are isolated by a uid range of their own and reach root only through that one pinned
helper, and the firewall rules they need are applied by a system unit at boot rather than by Elowen. Three
things a machine environment does not do, where a container did: capture a command's final working directory,
carry an AppArmor profile, and accept named volumes.

One setting disappeared: the advisory **disk threshold** for environments, in both Project and Sites settings.
Nothing ever measured or enforced it. So did the switch that compacted ChatGPT conversations on the provider's
side — every conversation is now compacted by Elowen on its own warm context, which is what that switch was an
alternative to.

### Compatibility

- Plugin UI API stays **16**, shipped as `elowen-plugin-ui-kit` 0.11.0. The minor is additive types and theme
  tokens only, so a bundle built against 0.10.0 keeps working. Shared-helper API stays **4**
  (`elowen-plugin-shared` 0.3.0) and `requiresSharedApi` is still an exact match.
- The Sites plugin requires core **0.28.42**; the image plugins require **0.28.41**.
- The minimum supported Node.js version remains **22.12.0**.

### Registry plugin releases in the same period

Registry plugins release on their own stream:

- **sites 0.11.2** — observed certificate readiness, deletion handed to the daemon, persistent machine
  environments, and an address the agent can name from any of its own processes.
- **browser 0.3.11** — the separate project browser was removed, leaving one account browser; a managed
  project's persistent profile reopens, and a failed teardown resumes.
- **todo 0.14.6** — `TaskCreate` takes unambiguous sibling tokens in `blockedBy`, and string ids only.
- **image-gen 0.2.4** and **image-edit 0.2.4** — the image model is picked from the shared model picker.
- **skills 0.3.6** — `CreateSkill` writes its front matter through a real YAML serializer.
