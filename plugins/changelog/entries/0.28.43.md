This is a small corrective release. When you start a new conversation, Elowen asks where it should run, and
until now that answer did not always survive the question. The project you pick is now the project the
conversation actually works in, from the first message onwards.

### Chat

- Answering "Where should this conversation run?" moves the conversation straight away. The project named in
  the chat header changes the moment you pick, and your first message runs in that project. Previously the
  header went on naming the previous target and you had to pick the project a second time, from the picker in
  the chat header, before anything ran there.
- Picking a project from the chat header behaves the same way, so the two places that name a conversation's
  project can no longer disagree with each other.
- The question stays on screen while it is still yours to answer. Moving to another conversation puts it
  away, but a dropped connection or coming back to the tab no longer dismisses it unanswered.
- The MCP and language-server rows of the telemetry panel no longer stay empty for the rest of a conversation
  when you answer the question while that panel is still loading.

### Compatibility

- Plugin UI API stays **16** and the shared-helper API stays **4**; no plugin needs rebuilding.
- The minimum supported Node.js version remains **22.12.0**.

### Registry plugin releases in the same period

- **github 0.1.16** — the project drawer reads a managed project at its own guest root and asks only about the
  selected project.
