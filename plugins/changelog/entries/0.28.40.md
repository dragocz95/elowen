This is the largest release since 0.28.25. A Project can now own a real, persistent Linux environment; the
command palette became a search box for the whole app; long conversations keep their context far longer;
and a daemon restart no longer interrupts what Elowen was saying to you.

### Projects that own a machine

A Project can now be **managed**: it runs in its own isolated container that stays alive between turns, so
a build, an installed dependency or a checked-out branch is still there the next time you ask. Files,
shell, git, browser, editor, language servers, MCP servers and the codebase index all reach into that
container instead of the server's own filesystem, and it ships with the tools they need, including ripgrep
for content search and LibreOffice for office previews.

An administrator turns this on in **Projects → New project**, where the *Execution target* field offers a
managed environment instead of a host directory. A managed project is private until it is deliberately
shared, and its environment starts only on first use. Existing projects keep working exactly as before.

### Session control from any chat

- On Discord, Microsoft Teams, Telegram and WhatsApp, `/project` opens a project picker; pick one and the
  conversation stays in that project, including after a restart. `/project <name>` skips the picker.
- In the CLI, `/cd` moves the working directory of the current session, and `/sandbox` opens a chooser for
  your Git worktrees. The web has the same chooser as a drawer.
- `/context` continues one of your own conversations inside a channel.

### Search that understands what you meant

Press **⌘K** (**Ctrl+K** on Windows and Linux) anywhere in the app. The palette now searches pages,
Settings and Account sections, installed plugins and actions. When the literal match is thin it re-ranks
the results by meaning, so "where do I change the digest model" lands on the right row; when nothing
matches at all, it offers to ask a model instead of showing you an empty list.

The agent's own tool search improved in the same way: `ToolSearch` now ranks by meaning as well as by
keyword, and it returns matching **skills** beside the tools, so a capability gets found even under a name
nobody guessed.

### One place that answers "which model does what"

**Settings → Models → Model roles** now sits above the model catalog and names every role in one table:
the default chat model, the utility model behind conversation titles and memory distillation, the daily
digest model, and the embedding provider, model and dimensions.

Your personal equivalents live in **Account → Models**: primary model, thinking level, vision fallback and
compact model, with any per-project model pins listed and clearable right beside them.

### Longer conversations, less waste

Two changes make a long conversation cheaper and less likely to hit a context limit:

- **In-session compaction.** The summary that compacts a conversation is now written inside the session's
  own warm context instead of a separate cold request, which is where the cached prefix was being thrown
  away.
- **Cold context trimming.** When a turn starts after the cache has expired, historical scaffolding, old
  tool output and older images are folded down to short markers, and an oversized tool result is written to
  a file that Elowen can read back on demand. Your own messages and the most recent turn are never touched.

### A new left navigation

The navigation column was rebuilt: it collapses to a narrow rail with tooltips, and you can **drag the rows
into the order you want**. Release notes and Account now sit in the instance group under Settings — which
is where you are reading this.

The page you are on is the new **What's new** entry. It ships inside the product, so every update brings
its own notes, and the badge on the navigation entry counts the releases you have not opened yet. Notes are
shown in your own language when a translation shipped with them.

### The conversation tree

The conversation switcher is now one list for everything, and it draws the work that hangs off a
conversation as branches beneath it:

- **Sub-agents** appear under the conversation that spawned them, up to three levels deep, from the `⋯`
  menu on the row.
- **Scheduled jobs** appear as their own branch; clicking one opens the conversation the run landed in. A
  job can now keep a dedicated conversation across runs, or start each run in an empty one.
- Every row shows whether it is working, finished or failed, and whether it has unread replies.

### Images from your ChatGPT account

Image generation and editing no longer need a separate API key. If you have connected a **ChatGPT account**
under Settings → Models → Connected accounts, the image plugins can render through it directly. The
account's credentials never reach plugin code — the host does the call and hands back the finished image.

### Restarts you do not notice

Elowen used to finish, or abandon, whatever it was doing when the service was asked to stop. It now saves
its place and exits promptly, then quietly continues the same answer after it comes back. No "the daemon
restarted" message, no duplicated reply, no lost turn. If a tool call was cut off mid-flight, Elowen is
told to verify the result before repeating it.

### Shared project memory

An administrator can turn on **Shared memory** under Projects → the project → Memory. Members then see one
common pool of memories beside their private ones. Leaving the sharer list empty means every member of the
project; naming people limits it to them. Every shared memory keeps its author.

### Faster dashboard, richer chat

- `/dash` no longer waits on a full token rollup across your whole history before it paints, so it appears
  promptly instead of hanging on an empty page. The daily recap also rotates between several generated
  variants.
- Diffs in chat are rendered the way the CLI renders them: syntax-coloured rows, a full-row tint for added
  and removed lines, and a line-number gutter that stays out of your copied selection.
- The composer puts the work-mode switch beside send, pulses the stop button while a turn runs, and folds
  the model picker and new-chat action into a `⋯` menu on a phone.
- The browser plugin's live view can dock over the chat; the transcript text now wraps beside it, and when
  a question is waiting for you the card says so and hands you back to it.
- The editor plugin's page at `/p/editor` now declares itself a workbench, so it uses the full width of the
  window instead of the shared reading column.

### For plugin authors

- `ctx.images` renders and edits images through an API-key provider or a connected ChatGPT account, without
  the credential ever entering plugin code.
- `ctx.registerNavBadge` puts a count on a plugin's own navigation entry.
- `ctx.persistToolOutput` stores a large tool output as a file the agent can read back.
- WebSocket routes are declared in the manifest and served at `/ws/plugins/<plugin>/…`, authenticated with
  a one-shot ticket.
- A plugin page can declare `layout: workbench`, a settings section can belong to the plugin's own detail
  page, a readiness check can contribute several rows, and a response body can be streamed instead of
  buffered.
- A plugin can register a **picker command** that each surface draws as its own chooser, which is how
  `/sandbox` works on both the CLI and the web.

### Compatibility

- Plugin UI API is **16** (`elowen-plugin-ui-kit` 0.10.0). Shared-helper API is **4**
  (`elowen-plugin-shared` 0.3.0); `requiresSharedApi` is an exact match, so a plugin still declaring 3 must
  be rebuilt.
- Plugins that use a project environment declare `requiresCore` **0.28.35**. The image plugins declare
  `requiresCore` **0.28.36**.
- The minimum supported Node.js version remains **22.12.0**.

### Registry plugin releases in the same period

Registry plugins release on their own stream: browser 0.3.8, cronjob 0.4.7, discord 0.3.18, editor 0.3.8,
image-gen 0.2.3, image-edit 0.2.3, lsp 0.1.5, msteams 0.7.0, sites 0.10.6, stats 0.2.4, telegram 0.2.14,
whatsapp 0.2.17, todo 0.14.3, skills 0.3.5, voice-bot 0.1.1 and onedrive 0.2.3. The MCP plugin was retired
