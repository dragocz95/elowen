A Project is now the hub. A plugin contributes its own panels to a project instead of claiming a top-level
navigation entry, so sandbox environments and repositories are reached from the project they belong to, and
each plugin keeps its own data and its own connection.

This release also carries versions 0.28.12 to 0.28.16, which were tagged during development and never
published.

### Added

- A plugin can declare the controls it cannot work without and the controls it publishes for others. The
  daemon refuses to enable a plugin whose required control nothing provides, and names the plugin that would
  have provided it. Before this, such a plugin enabled happily and then quietly did nothing.
- Plugins contribute panels to an account, to a project and — for administrators — to a user, and can hide
  their own panels from an account that cannot use them. A capability that depends on a connection you have
  not made stays out of the way instead of showing an empty labelled tab.
- Platform account links for Discord, Microsoft, Telegram and WhatsApp are a click-through row opening a
  drawer, offered only where a message from that platform could actually arrive.
- Sub-agent and task cards show live elapsed time, stable task identifiers and confirmed bulk clearing.

### Changed

- Account and Settings are built from section cards. The first click in a section opens a right-hand drawer;
  a centred window is only ever the second step from a drawer.
- Moved to PI 0.84.3 for the wider model catalogue.

### Fixed

- Public OAuth callbacks require HTTPS.
- Deleting an account drains its running processes first.
- Sandbox execution ownership and leases are enforced per account.
- Compacted usage stays attributed to its original UTC day.
- Nine of eleven navigation icons were silently rendering a puzzle piece.
