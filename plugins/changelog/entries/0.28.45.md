This hotfix corrects the Sandbox host readiness report for managed Projects and persistent Sites. Existing
systemd-nspawn environments remain valid even when their disk records retain a historical Podman image name.

### Managed environments

- **Settings → Plugins → Sandbox → Host runtime** now determines each environment's owner from its persisted disk
  runtime, which is the same value used to select the runtime that starts and restores it.
- A systemd-nspawn environment with an older `localhost/elowen-project-base:*` source reference is reported as
  ready and no longer receives an incorrect instruction to delete and recreate it.
- A non-deleted environment with a missing or unsupported disk runtime is still reported as belonging to the
  removed Podman runtime. Deleted environment records remain excluded from readiness.

### Compatibility

- No migration or environment recreation is required for valid systemd-nspawn environments.
- Plugin UI API remains 16, shared-helper API remains 4, and the minimum Node.js version remains 22.12.0.
