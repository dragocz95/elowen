This release makes Settings easier to navigate, shows resource use for managed Projects, corrects Sandbox runtime
readiness and removes the application runtimes previously owned by individual Sites.

### Settings

- Settings now opens as a searchable overlay above the page you are using. Search and keyboard navigation cover
  both built-in sections and plugin settings without losing the underlying route.
- Managed Project environment limits and networking save directly from their drawer and show the shared autosave
  status.

### Managed Projects

- Project rows now show sampled CPU, memory and disk usage from their systemd-nspawn environment, including clear
  loading, stopped and unavailable states.
- **Settings → Plugins → Sandbox → Host runtime** determines each environment's owner from its persisted disk
  runtime. A valid systemd-nspawn disk with an older Podman image name no longer receives an incorrect deletion
  warning, while a missing or unsupported runtime remains reported as legacy.

### Agent guidance and Editor

- Core, platform, scheduled, CLI mode and delegated-agent instructions now use shorter Markdown sections while
  preserving their runtime placeholders, permission boundaries and continuity rules.
- Editor 0.4.4 removes the active path from the top toolbar and shows its complete host or managed-environment path
  with a storage icon in the bottom status bar.

### Sites

- Sites now publishes immutable static releases or forwards to an application already running inside an explicit
  managed Project. The proxy kind owns only the address, TLS and access layer; lifecycle and logs stay with the
  Project.
- Command and PHP publication, runtime controls, logs, process supervision and runtime sockets have been removed,
  together with the separate per-Site environment lifecycle, snapshots and execution tools.
- Historical command, PHP and environment rows remain dormant and invisible for audit. Sandbox retires any
  verified historical Site machine without deleting its rows, snapshots, storage, backups or UID allocation.

### Compatibility

- Existing valid managed Project environments require no migration or recreation.
- Sites 0.12.0 requires core 0.28.45.
- Plugin UI API remains 16, shared-helper API remains 4, and the minimum Node.js version remains 22.12.0.
