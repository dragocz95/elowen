This release makes Settings easier to navigate, shows resource use for managed Projects, corrects Sandbox runtime
readiness and removes the separate persistent environment previously owned by each Site.

### Settings

- Settings now opens as a searchable overlay above the page you are using. Search and keyboard navigation cover
  both built-in sections and plugin settings without losing the underlying route.
- Managed Project environment limits and networking save directly from their drawer and show the shared autosave
  status.

### Managed Projects

- Project rows now show sampled CPU, memory and disk usage from their systemd-nspawn environment, including clear
  loading, stopped and unavailable states.
- **Settings → Plugins → Sandbox → Host runtime** determines each environment's owner from its persisted disk
  runtime. A valid systemd-nspawn disk with an older Podman image name no longer receives an incorrect deletion
  warning, while a missing or unsupported runtime remains reported as legacy.

### Sites

- Proxy publications remain a thin address, TLS and access layer over an application running inside an explicit
  managed Project. Static immutable releases remain available.
- The separate per-Site environment lifecycle, controls, snapshots and execution tools have been removed. Legacy
  rows and backups remain retained as dormant audit data, and any verified historical machine is retired without
  deleting that data.
- Command and PHP publications remain supported for compatibility and will be handled separately in a later
  release.

### Compatibility

- Existing valid managed Project environments require no migration or recreation.
- Sites 0.12.0 requires core 0.28.45.
- Plugin UI API remains 16, shared-helper API remains 4, and the minimum Node.js version remains 22.12.0.
