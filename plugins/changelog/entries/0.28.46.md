This release makes Projects easier to scan, brings Account and Settings into one consistent overlay model, removes the retired Sandbox workspace layer and hardens managed Project networking and Site page capture.

### Projects and navigation

- Projects now appear as responsive cards with branch, team, location and measured CPU, memory and disk usage. The card and detail drawer share one bounded resource snapshot and keep the last complete sample during a partial refresh.
- Account now opens above the current page like Settings. Settings and Account each occupy one navigation row, and phone Settings keeps a persistent section strip for quicker movement.
- Meter values, project detail links, wheel input and touch targets now match the state and geometry they actually represent.

### Repository work

- Repository work now uses native Git worktrees. The retired account-owned Sandbox workspace picker and its CLI, web, plugin and delegated-agent plumbing have been removed.
- Background delegates and nested delegated-session navigation now survive prompt refresh and follow one caller-relative transcript path.

### Managed Projects and security

- Environment storage roots, readiness, publication recovery and shutdown now fail closed when ownership or liveness cannot be proved. Publication work drains before shutdown, and recovered environments thaw only after their transport state is safe.
- The privileged machine helper performs validated tree operations through opened file descriptors and stages root-owned files outside the service account's control.
- Managed machines remain blocked from link-local metadata and cloud-platform services. When Azure platform DNS is the selected resolver, only TCP and UDP DNS to that exact address is allowed; HTTP and every other platform request remain blocked.
- Migrated persistent Project roots now restore the rootfs recipe's required `systemd-networkd` enablement before startup. Shared-network startup and EnvironmentStatus require `host0` carrier and a global address instead of treating a running guest systemd as network-ready.

### Sites and Browser

- New Sites publications now use one model only: an address that proxies directly to an application already running inside an active managed Project. Nothing is copied, built or started by Sites.
- Existing legacy file releases continue serving, rolling back and deleting, but they cannot be created or published again.
- Browser 0.4.0 renders Site pictures in a fresh throwaway Chrome profile through an enforcing proxy pinned to the exact published HTTPS origin. Cross-origin redirects, private addresses, literal-IP alternatives and DNS rebinding are refused, and timeout or plugin shutdown retains cleanup ownership until a late browser launch is closed.

### Registry plugin releases

- **Browser 0.4.0** adds the Sites-only, origin-pinned capture control.
- **Sites 0.14.0** uses managed Project proxy publication only, adds page pictures and retains read, rollback and delete compatibility for existing file releases.

### Compatibility

- Elowen core is 0.28.46. Plugin UI API remains 16, shared-helper API remains 4, and Node.js 22.12.0 remains the minimum.
- Browser 0.4.0 requires core 0.28.46. Sites 0.14.0 requires core 0.28.45 and uses Browser 0.4.0 when page pictures are available.
